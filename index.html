Aprenda Git e GitHub do zero

Sete aulas curtas para guardar o histórico do seu código, trabalhar em equipe e publicar seus projetos. Cada aula tem comandos que você pode copiar e testar no seu terminal.

O que são Git e GitHub

Git é um programa que roda no seu computador e registra cada versão do seu projeto. Você pode voltar a qualquer versão antiga e trabalhar em ideias diferentes sem bagunçar o código principal.

GitHub é um site que guarda seus repositórios Git na internet. Ele serve para fazer backup, compartilhar código e colaborar com outras pessoas.

  • Repositório: pasta do projeto com todo o histórico.
  • Commit: uma foto do projeto em um momento, com uma mensagem.
  • Branch: uma linha paralela de trabalho.

Instale o Git em git-scm.com e crie uma conta gratuita em github.com.

Configure seu nome e e-mail

Faça isso uma única vez. Esses dados aparecem em cada commit que você criar.

$ git config --global user.name "Seu Nome"
$ git config --global user.email "voce@email.com"
$ git config --global init.defaultBranch main

Use o mesmo e-mail da sua conta do GitHub para os commits aparecerem no seu perfil.

Crie seu primeiro repositório

O fluxo básico tem três passos: alterar arquivos, escolher o que entra no commit (add) e salvar (commit).

# cria a pasta e inicia o Git
$ mkdir meu-projeto && cd meu-projeto
$ git init

# crie um arquivo, depois:
$ git status
$ git add .
$ git commit -m "Primeiro commit"
$ git log --oneline

Escreva mensagens que dizem o que mudou, como "Adiciona formulário de contato". Daqui a um mês você agradece.

Trabalhe com branches

Crie uma branch para cada tarefa. A main fica estável e você junta o trabalho quando estiver pronto.

$ git switch -c nova-funcionalidade
# ...edite, faça add e commit...
$ git switch main
$ git merge nova-funcionalidade
$ git branch -d nova-funcionalidade

Se duas branches mudarem a mesma linha, o Git avisa de um conflito. Abra o arquivo, escolha qual versão manter, apague as marcações <<<<<<< e faça um novo commit.

Envie seu código para o GitHub

Crie um repositório vazio no GitHub, copie a URL dele e conecte ao seu projeto local.

$ git remote add origin https://github.com/usuario/meu-projeto.git
$ git push -u origin main

# depois, no dia a dia:
$ git pull
$ git push

# para baixar um projeto existente:
$ git clone https://github.com/usuario/projeto.git

Se o GitHub pedir senha, use um token de acesso pessoal ou o GitHub CLI (gh auth login). Senhas comuns não funcionam mais no terminal.

Pull request: proponha mudanças

Um pull request pede para o dono de um projeto incorporar o seu trabalho. É assim que se contribui com projetos open source e se revisa código em equipes.

  • Faça um fork (cópia do projeto na sua conta) ou crie uma branch no repositório da equipe.
  • Faça seus commits e envie a branch com git push -u origin nome-da-branch.
  • No GitHub, clique em Compare & pull request, descreva a mudança e envie.
  • Responda aos comentários da revisão com novos commits na mesma branch.

Desfazendo erros

# descarta mudanças ainda não commitadas em um arquivo
$ git restore arquivo.txt

# tira um arquivo do add, sem perder as mudanças
$ git restore --staged arquivo.txt

# corrige a mensagem do último commit
$ git commit --amend -m "Mensagem certa"

# cria um commit que desfaz outro (seguro para código já enviado)
$ git revert a1f3c9e

Evite git reset --hard e git push --force até entender bem o que fazem: eles podem apagar trabalho de forma definitiva.
